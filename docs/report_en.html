Executive summary

November 2026's Patch Tuesday was smaller than October's. The full CVRF fell from 1,760 CVEs to 1,362, and core Microsoft from 1,419 to 1,092. Microsoft assigned all 1,092 core CVEs, and 1,091 of them were first published in the 10 November release.

Not everything fell with the count. The heavy tier — updates that need change control — rose from 79 to 95 in core, its highest since August. Core Critical fell from 77 to 64. For the second month running, the count and the heavy tier moved in opposite directions.

There is one zero-day this month (Microsoft's definition: exploited or publicly disclosed), and Microsoft flags it as exploited (confirmed exploitation). It is rated Moderate, not Critical. CISA added the same CVE to the KEV catalog on release day (KEV retrieved 12 November).

Conclusion in one line

The count fell; the heavy tier rose. Once again, the CVE count did not track how heavy the month's patching is.

Terms: "full CVRF" and "core Microsoft"

Full CVRF — every CVE in MSRC's monthly document, including Edge/Chromium, Azure Linux package advisories and Azure cloud advisories. Press tallies differ because they cut this population differently.

Core Microsoft — the full CVRF minus CVEs whose affected products are all Azure Linux packages or all Edge/Chromium. Azure cloud advisories stay in core (this month's twenty azure_cloud CVEs). A CVE whose affected products include any Microsoft product also stays in core. The split works from product identifiers (ProductIDs resolved to product names), not from CVE titles. This month: 1,092 core and 270 excluded — the excluded side is 166 Edge/Chromium and 104 Azure Linux. Edge/Chromium advisories, absent last month, are back.

Count and weight: what did not move together

The count fell, but the measures of how heavy the response is did not move with it.

  • The heavy tier (T2+T3, core) rose from 79 to 95. Its share of core went from 5.6% to 8.7%. At 95, it is the highest since August (93 in September).

  • By product category, SQL/Dynamics accounts for 54 of the heavy tier, double last month's 27. Office went from 35 to 26 and Exchange from 7 to 9 (last month's figures come from recounting the October freeze-time copy with this month's classifier, v3).

  • Core Critical fell from 77 to 64: 48 remote code execution and 16 elevation of privilege, 64 in all.

  • Critical across the full CVRF fell from 174 to 69. Most of the fall is on the excluded side, which last month held 97 Azure Linux Critical CVEs; this month the excluded side has five Critical CVEs (four Chromium, one CivetWeb).

A lower count does not mean a lighter deployment plan. Last month the count was the highest and the heavy tier fell; this month the count fell and the heavy tier rose.

Implications and recommended actions

These are recommendations drawn from this report's analysis, not settled regulatory requirements. Specific supervisory expectations should be confirmed against primary sources.

1. What to monitor (continued)

  • Do not use the CVE count as a threat indicator. This month it fell 22.6% on last month, yet the heavy tier rose; last month it was the other way round. For two months running, the count has not moved in step with defensive load.

  • Track the tier that needs change control instead. This month it rose from 79 to 95 in core, 54 of them SQL/Dynamics. Even a month with a smaller total can carry a heavier deployment plan than the month before.

  • But a count is not a measure of effort. Effort depends on how many products the updates span, and this report does not measure that (the same limitation as last month).

2. Decouple triage from the severity label (continued)

  • None of this month's 69 Critical CVEs is confirmed exploited; the one confirmed-exploited CVE is Moderate. From July to November, no confirmed-exploited CVE in any month was Critical.

  • May, on the other hand, did have a confirmed-exploited Critical. What the five-month record shows is that the severity label itself is an unreliable basis for prioritisation.

  • The alternative is unchanged: combine CISA KEV, EPSS and asset reachability.

  • Check the population before reading a Critical count. Of this month's 69 Critical CVEs across the full CVRF, five are on the excluded side.

3. Emergency patch SLA

  • This month's confirmed-exploited CVE, CVE-2026-124194, was added to CISA KEV on 10 November (KEV retrieved 12 November). Start deploying it the same day. KEV sets a due date of 24 November (the deadline for US federal agencies).

  • According to the vendor's CVSS vector, the attack is network-based, needs no prior privileges and has low complexity — but it requires user interaction. The impact is spoofing, with confidentiality impact rated High. The CVSS base score is 6.5; six products are affected (Microsoft 365 Apps and Office LTSC 2021 and 2024).

  • The temporal Exploit Code Maturity metric is High (E:H), consistent with the CVRF's exploitation entry ("Exploitation Detected").

  • A Moderate rating and a 6.5 base score are the kind of values that a severity or base-score cut-off pushes down the queue. Both Microsoft's exploitation flag and the KEV listing catch this one.

4. Check your own filter (continued)

  • Following record 4 in the last issue (a zero-day that was only publicly disclosed fell outside the matched set), this issue adds "publicly disclosed" to the conditions for the KEV/EPSS matched set (matching rule v3). With no publicly-disclosed-only zero-day this month, the change brought no new CVE into the set.

  • This month's matched set is 916 CVEs (1,164 last month). The confirmed-exploited CVE is in it and was picked up as a new KEV addition.

  • Some CVEs in KEV still fall outside the set. CVE-2026-123158 (OpenSSH; an Azure Linux advisory on the excluded side) is in this month's CVRF and was added to CISA KEV on 9 November, but the CVRF has no exploitation entry for it. Rated Important and uncredited, it meets none of the matching conditions (confirmed exploited, publicly disclosed, heavy tier, Critical, externally credited), so it does not appear in the KEV table.

  • When you match external threat intelligence against your own estate, check each month's numbers for what falls outside the set you are matching.

5. Edge/Chromium auto-update (continued)

  • This month's CVRF carries 166 Edge/Chromium advisories (none last month, 24 the month before), four of them Critical. This report cannot say why the count swings.

  • The point stands regardless of the count. Applications that embed Electron/CEF (Teams, Slack, VS Code and others) do not benefit from the browser's auto-update. Using an SBOM to find those dependencies remains necessary.

6. Business continuity for AI dependence (continued)

  • Where AI is built into a workflow, treat dependence on a top-tier model as a business-continuity concern, and make model redundancy and fallback the default.

Appendix: method, sources, accountability record

This appendix records the process behind the conclusions, for reproducibility and accountability.

1. Purpose and questions

The question carries over from last issue: what monthly vulnerability data can tell us about defensive load and actual risk. This issue also checked how the measures of weight moved when the count fell after last issue's high.

2. Sources

This issue rests on primary data only and cites no press or secondary analysis.

  • MSRC CVRF API v3.0 — monthly security updates as per-CVE structured data, including acknowledgements, severity, exploitation status, affected products, CVSS vectors and FAQs.

  • CISA KEV catalog — the catalog of known exploited vulnerabilities, cross-checked against this month's CVEs.

  • FIRST EPSS — the estimated probability that exploitation activity will be observed within 30 days.

3. How the data was acquired

Primary data was fetched in the acquisition environment and frozen two days after Patch Tuesday (07:18 on 12 November), the same interval as in August to October. From this issue, copies of the CVRF and the KEV catalog as of the freeze are kept with the frozen figures (a recount of the copy was confirmed to reproduce the frozen figures). Compared with the previous day's fetch (11 November, CVRF version 2026-11-10T08:00), core (1,092), core Critical (64), the heavy tier (95) and the single zero-day were unchanged. The total rose by twenty from 1,342; all twenty are on the excluded side (Azure Linux), and eighteen were first published on 11 November. Critical across the full CVRF rose by one from 68 (CivetWeb, CVE-2026-124040, excluded side). Credited rose by one (1,076 → 1,077). KEV was retrieved on the day of the freeze (12 November; catalog version 2026.11.10). EPSS scores are dated 2026-11-10, the latest FIRST had published at retrieval. Most of the release's CVEs have no EPSS score yet (seven of the 916 in the matched set have one).

4. Method, in sequence

  1. Primary data fetched two days after Patch Tuesday.

  2. Compared with the previous day's fetch: core, core Critical, the heavy tier and the zero-day had not moved. The total rose by twenty on the excluded side, and full-CVRF Critical and credited each moved by one (section 3).

  3. Frozen, with copies of the CVRF and the KEV catalog as of the freeze.

  4. KEV and EPSS retrieved for this month's matched set.

  5. For the zero-day, the exploitation entry, CVSS vector and affected products were read in the original CVRF.

  6. With the heavy tier up, its breakdown by product category was checked. For the comparison with last month, the October freeze-time copy was recounted under this month's classifier (v3) (section 5, record 1).

5. Record of the work

For accountability, the judgements made and their grounds are recorded.

Record 1: Table 5's classifier moves to v3. Under v2, Microsoft component names resolved from product identifiers (HEVC, AD CS, WebDAV and others) matched no rule and stayed in "Other". v3 assigns them to their categories. Recounting the October freeze-time copy (the same CVRF version as the frozen figures) under v3 takes "Other" from 62 to 11. On the recount, the copy's total, Critical and core Critical still match the frozen figures (1,760, 174, 77). The population split (core / excluded) stays at v2 and is unaffected by v3. This issue's core, Critical and heavy-tier counts use the same rules as earlier issues.

Record 2: the matching rule moves to v3. Following last issue's record 4, "publicly disclosed" was added as a condition for the KEV/EPSS matched set. This month has no zero-day that is only publicly disclosed, and the change added no CVE to the set.

Continuation 3: exploitation status within one document. The issue before last recorded that, among confirmed-exploited CVEs, the CVSS temporal metric agreed with Threats for some and not for others. This month's confirmed-exploited CVE (CVE-2026-124194) has Exploit Code Maturity High (E:H), consistent with Threats' "Exploitation Detected". That makes a second month of agreement, but two agreeing cases are not enough to rely on the field. This report still derives its exploited flag from Threats.

Continuation 4: do not tie a credit to an entity on circumstantial evidence. The July issue asserted that "Kugelblitz" was a particular in-house AI tool, and withdrew the claim after checking primary sources. That discipline holds. Nothing is claimed about activity stopping or continuing now that the name has been at zero for three months.

6. What the conclusions finally rest on, and their limits

Grounds relied on (confidence: high)

  • The frozen figures are a mechanical tally of primary data. Against the day before, core, core Critical, the heavy tier and the zero-day are confirmed unchanged (the total rose by twenty on the excluded side).

  • Copies of the CVRF and the KEV catalog as of the freeze are kept, and recounting the copy reproduces the frozen figures.

  • The population split is again based on product identifiers, with every product identifier resolved (zero unresolved). The 270 excluded are 166 Edge/Chromium and 104 Azure Linux.

  • The preconditions for the confirmed-exploited CVE (network, no prior privileges, user interaction required, low complexity) come from the CVRF's CVSS vector. The KEV listing date and due date come from the KEV catalog retrieved on the day of the freeze.

Limits (confidence: unsettled / caution)

  • Why the heavy tier rose is not known. It is concentrated in SQL/Dynamics, but the CVRF does not say why.

  • The heavy tier is counted, but how many products it spans is not measured. A higher count cannot be read as more work.

  • The category comparison with last month uses the October copy recounted under v3. It differs from last issue's Table 5 (v2).

  • Why the Edge/Chromium count swings so much from month to month is not known.

  • Actual attacks and observed techniques for the confirmed-exploited CVE were not checked. The preconditions are an assessment from the CVRF's CVSS vector, not something observed in the field.

  • EPSS is as of 2026-11-10. It changes daily, and most of the release's CVEs have no score yet.

7. How to reproduce

This issue's figures can be reproduced with the collection and freeze tools in the public msrc_monitor repository (Python 3.12, network access to the MSRC API). MSRC revises past months after the fact, so identical values are not guaranteed; post-freeze revisions are recorded separately.

  • Fetch this month's primary data: python collect.py 2026-Nov

Terms
CVRF
The machine-readable vulnerability feed Microsoft publishes each month (MSRC CVRF v3.0) — this report's primary data.
Full CVRF / core Microsoft (re-listings)
“Full CVRF” is every CVE record the feed returns for a month, which mixes in Edge/Chromium (fixed by Google and re-listed by Microsoft), Mariner (Azure Linux) and Azure cloud services. “Core Microsoft” is the same month with those re-listings excluded. The two populations are reported side by side.
Zero-day
In this report, a CVE that Microsoft's data flags as exploited, or as publicly disclosed, or both.
Confirmed exploitation
Microsoft's own exploitation flag is set for that CVE. This is a separate source from CISA KEV, and the two can disagree in either direction.
KEV
CISA's Known Exploited Vulnerabilities Catalog — vulnerabilities CISA has confirmed as exploited. Cross-vendor listings are recorded in the Cross-vendor KEV/EPSS section of this site.
EPSS
The probability that exploitation activity will be observed within 30 days (0 to 1). It is not a severity score.
