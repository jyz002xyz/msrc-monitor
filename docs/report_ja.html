要旨

2026年11月の Patch Tuesday は、前月より件数が少なかった。CVE 全体は 1,760件から 1,362件に、MS本体相当は 1,419件から 1,092件に減った。本体相当の 1,092件はすべて Microsoft が採番したもので、うち 1,091件は 11月10日の月例で初めて公開された。

ただし、すべてが件数と同じ向きに動いたわけではない。変更管理が必要な重い層は、本体相当で 79件から 95件に増え、8月以降で最も多くなった。 本体相当の Critical は 77件から 64件に減った。件数と重い層が逆の向きに動いたのは、2か月連続である。

ゼロデイ（Microsoft の定義では、悪用が確認されたもの、または公開済みのもの）は1件で、Microsoft が悪用を確認している（悪用確認）。 深刻度は Moderate で、Critical ではない。この CVE は月例の当日に CISA KEV にも載った（KEV の取得は 11月12日）。

結論（一言）

件数は減ったが、重い層は増えた。今月も、件数の増減は対応の重さと一致しない。

用語解説：「CVRF全体」と「MS本体相当」

CVRF全体 — MSRC の月次文書に載るすべての CVE。Edge/Chromium、Azure Linux のパッケージの勧告、Azure クラウドの勧告も含む。報道各社の集計が食い違うのは、この母集団の切り方が違うためである。

MS本体相当 — CVRF全体から、影響製品がすべて Azure Linux のパッケージである CVE と、すべて Edge/Chromium である CVE を除いた母集団。Azure クラウドの勧告は本体相当に入る（今月の azure_cloud 20件は本体相当の側）。影響製品に Microsoft の製品が一つでも混じる CVE も本体相当に入る。製品識別子（ProductID を製品名に引き当てたもの）で判定し、CVE のタイトルの文字列は使わない。今月は本体相当 1,092件・除外 270件で、除外の内訳は Edge/Chromium 166件と Azure Linux 104件である。 前月は1件も無かった Edge/Chromium の勧告が、今月は戻ってきた。

悪用確認のあった CVE は、5か月続けて Critical ではない

今月、悪用が確認されたのは CVE-2026-124194（Microsoft Outlook のなりすまし） の1件で、深刻度は Moderate である。今月の Critical 69件には、悪用が確認されたものが1件も無い。

7月から11月までの5か月は、毎月悪用確認があり、そのどれも Critical ではなかった。ただし、5月には Critical の悪用確認が1件あった。Critical なら悪用されない、という意味ではない。 Critical だけを見て対応する運用では、この5か月の悪用確認をすべて見落とす、という意味である。今月の1件は、Important ですらなく Moderate である。

この CVE は CISA KEV にも載っている（2026年11月10日に収載。KEV の取得は 11月12日）。Microsoft の悪用確認と KEV への収載が、両方そろっている。 今月、公開済みだけのゼロデイは無い。

総数と重さ：同じ向きに動かなかったもの

件数は減ったが、対応の重さを表す指標は、それと同じ向きには動かなかった。

  • 重い層（T2+T3・本体相当）は 79件から 95件に増えた。 本体相当に占める割合は 5.6% から 8.7% に上がった。95件は8月以降で最も多い（9月は 93件）。

  • 重い層を製品カテゴリで見ると、SQL/Dynamics が 54件で、前月の 27件から倍になった。 Office は 35件から 26件に減り、Exchange は 7件から 9件に増えた（前月の値は、10月の凍結の写しを今月と同じ分類 v3 で数え直したもの）。

  • 本体相当の Critical は 77件から 64件に減った。 内訳は遠隔コード実行 48件・権限昇格 16件で、計 64件である。

  • 全体の Critical は 174件から 69件に減った。減った分の大半は、前月に除外の側にあった Critical 97件（Azure Linux）である。今月の除外の側の Critical は5件（Chromium 4件・CivetWeb 1件）である。

件数が減ったからといって、適用計画が軽くなるとは限らない。 先月は件数が最多で重い層が減り、今月は件数が減って重い層が増えた。

示唆と推奨アクション

以下は本レポートの分析に基づく推奨であり、確定した規制要求ではない。規制当局の個別の監督上の期待については、一次情報での確認を前提とする。

1. 監視指標（前号からの継続）

  • 「CVE件数」を脅威の指標にしない。今月は件数が前月より 22.6% 減ったが、重い層は増えた。先月はその逆だった。件数の増減と防御の負荷は、2か月続けて同じ向きに動いていない。

  • 代わりに、変更管理が必要な層の増減を毎月追う。今月は本体相当で 79件から 95件に増え、うち SQL/Dynamics が 54件である。件数の少ない月でも、適用計画は前月より重くなることがある。

  • ただし、件数は作業量ではない。 対象がいくつの製品にまたがるかで、手間は変わる。本レポートは、対象がいくつの製品にまたがるかを測っていない（前号と同じ限界）。

2. トリアージを深刻度ラベルから切り離す（前号からの継続）

  • 今月の Critical 69件に悪用確認は無い。悪用が確認された1件は Moderate である。7月から11月までの5か月、悪用確認のあった CVE に Critical は含まれていない。

  • 一方、5月には Critical の悪用確認があった。5か月の記録が示すのは、深刻度のラベルの高低で優先度を決めること自体が当てにならない、ということである。

  • 優先度の決め方は、前号と同じく、CISA KEV・EPSS・資産への到達性の組み合わせに移す。

  • Critical の件数は、母集団を確かめてから読む。 今月の全体の Critical 69件のうち、5件は除外の側である。

3. 緊急パッチ SLA

  • 今月の悪用確認1件（CVE-2026-124194）は、CISA KEV に 11月10日に収載されている（KEV の取得は 11月12日）。その日のうちに適用を始める対象として扱う。KEV の是正期限は 11月24日である（米国の連邦機関に向けた期限）。

  • ベンダーの CVSS ベクタによる攻撃の前提条件は、次のとおり。 ネットワーク経由で攻撃でき、事前の権限は要らず、攻撃の難易度は低い。ただし、ユーザーの操作が必要である。 影響はなりすましで、機密性への影響は「高」とされている。CVSS 基本値は 6.5、影響製品は 6件（Microsoft 365 Apps と Office LTSC 2021・2024）である。

  • 時間的指標の「悪用コードの成熟度」は「高」（E:H）で、CVRF の悪用状況の記載（悪用を検知）と一致している。

  • Moderate・CVSS 6.5 という値は、深刻度や基本値で足切りする運用では後回しにされる。 この1件は、悪用確認でも KEV への収載でも拾える。

4. 自分の絞り込み規則を点検する（前号からの継続）

  • 前号の記録④（公開済みだけのゼロデイが照合の対象から漏れていた）を受けて、今号から、KEV / EPSS の照合対象の条件に「公開済み」を足した（照合の規則 v3）。今月は公開済みだけのゼロデイが無いため、この変更で対象に加わった CVE は無い。

  • 今月の照合対象は 916件（前月 1,164件）である。悪用確認の1件はその中に入っており、KEV への新規収載として検出された。

  • KEV に載っていても、照合の対象に入らない CVE がある。今月の CVRF にある CVE-2026-123158（OpenSSH。除外の側の Azure Linux の勧告）は、11月9日に CISA KEV に収載されたが、CVRF には悪用状況の記載が無い。深刻度は Important でクレジットも無く、照合の条件（悪用確認・公開済み・重い層・Critical・外部クレジット）のどれにも当たらないため、KEV の表には出てこない。

  • 外部の脅威情報と自組織の資産を突き合わせるときは、突き合わせの対象から何が外れているかを、毎月の数字で確かめること。

5. Edge/Chromium 自動更新（前号からの継続）

  • 今月の CVRF には Edge/Chromium の勧告が 166件ある（前月 0件、前々月 24件）。うち4件が Critical である。件数が振れる理由は、本レポートでは分からない。

  • この項の要点は件数によらない。Electron/CEF を組み込んだアプリ（Teams、Slack、VS Code など）は、ブラウザの自動更新の恩恵を受けない。 SBOM でこうした依存を洗い出す必要は変わらない。

6. AI 依存の BCP（前号からの継続）

  • AI を業務の流れに組み込むなら、最上位モデルへの依存を BCP の対象とし、複数モデルの併用と、切り替えの設計を標準にする。

補遺：「AI関連」を示唆するクレジットの棚卸し

「Kugelblitz」というクレジット名は、7月に 39件、8月に 1件で、9月・10月・11月は 0件である。Critical には一度も現れていない。

この推移は解釈できない。 言えるのは、「その名前が3か月続けて出ていない」ことだけである。

8月号で記録した「AIフィジカルインターフェイス二号機」というクレジット文字列は、今月 36件ある。凍結値では、6月 2件・7月 10件・8月 13件・9月 38件・10月 3件・11月 36件である。今月の 36件はすべて本体相当の Important で、Critical も悪用確認も無い。正体は断定しない。 8月号と同じく、言えるのは、クレジットの文字列がこう書かれている、ということだけである。

今月のゼロデイ CVE-2026-124194 のクレジットの1つは、「（研究者名） using Claude with Anthropic」という文字列である。AI（Claude）を使ったことは、クレジットの文字列そのものに書かれている。 同じ文字列は10月にも1件ある。本レポートは、この記載から、発見の過程や AI の寄与の大きさを推定しない。記録するのは、文字列がこう書かれている、という事実だけである。
