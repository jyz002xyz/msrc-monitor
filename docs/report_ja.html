要旨

2026年10月の Patch Tuesday は、本レポートの観測範囲（2026年1月以降）で総数が最も多い月になった。CVE 全体は 1,186 から 1,760 へ、MS本体相当は 975 から 1,419 へ増えた。本体相当のうち Microsoft が採番した CVE は 973 から 1,417 へ増え、その差は本体相当の増加 444件と同じである。本体相当 1,419件のうち 1,411件は 10月13日の月例で初めて公開されたものである。

一方で、件数と同じ向きに動かなかったものがある。変更管理を要する重い層は、本体相当で 93 から 79 へ減った。 Critical は全体では 119 から 174 へ増えたが、本体相当では 114 から 77 へ減っている。 全体の Critical のうち 97件は除外の側（Azure Linux のパッケージ勧告）にある。

ゼロデイ（Microsoft の定義で、悪用が確認されたもの、または公開済みのもの）は3件で、悪用が確認されたものは1件である。 その1件は深刻度 Important で、Critical ではない。

結論（一言）

総数は観測範囲で最多になったが、重い層と本体相当の Critical は減った。件数の増え方と、対応の重さ・危険度の動きは一致しない。

用語解説：「CVRF全体」と「MS本体相当」

CVRF全体 — MSRC の月次文書に載る全 CVE。Edge/Chromium、Azure Linux のパッケージ勧告、Azure クラウドの勧告を含む。報道各社の集計が一致しないのは、この母集団の切り方が異なるためである。

MS本体相当 — CVRF全体から、影響製品がすべて Azure Linux のパッケージであるもの、またはすべて Edge/Chromium であるものを除いた母集団。Azure クラウドの勧告は本体相当に含まれる（今月の azure_cloud 14件は本体相当の側）。影響製品に Microsoft の製品が混在するものも本体相当に入る。分離は製品識別子（ProductID を製品名へ解決）で行い、CVE のタイトル文字列に依存しない。今月は本体相当 1,419 / 除外 341 で、除外の 341件はすべて Azure Linux である。Edge/Chromium の勧告は今月の CVRF に1件も無い。

悪用されたのは Critical ではない — 四か月続いた

今月、悪用が確認されたのは CVE-2026-96951（Windows Shell のセキュリティ機能のバイパス） の1件で、深刻度は Important である。今月の Critical 174件のうち、悪用が確認されたものは1件も無い。

悪用確認があり、そのどれも Critical でなかった月は、7月から10月まで4か月続いている。ただし5月には Critical の悪用確認が1件あった。Critical が悪用されないということではない。 Critical だけを見る運用では、この4か月の悪用確認をすべて取り落とす、ということである。

残る2件は公開済みで、悪用は確認されていない。

  • CVE-2026-108398（.NET Framework のセキュリティ機能のバイパス、Important） — ローカルで、認証済みの攻撃者による。

  • CVE-2026-92707（MessagePack-CSharp のサービス拒否、Moderate） — MessagePack-CSharp は、Visual Studio に含まれるオープンソースの部品で、分類の規則により本体相当に入っている。影響製品には Visual Studio 2022・2026 のほか、.NET の SignalR 用の MessagePack パッケージが挙がっており、Microsoft の製品が混在するため、規則（混在は本体相当）で本体相当に数えている。採番したのは Microsoft ではなく GitHub である。

総数と重さ：同じ向きに動かなかったもの

件数が増えた月に、対応の重さを表す軸は同じ向きに動かなかった。

  • 重い層（T2+T3・本体相当）は 93 から 79 へ減った。 本体相当に占める比率は 9.5% から 5.6% である。

  • 本体相当の Critical は 114 から 77 へ減った。 その内訳は遠隔コード実行 59件・権限昇格 14件・なりすまし 3件・情報漏えい 1件で、合計 77件である。

  • 全体の Critical が 174 へ増えたのは、除外の側の Critical が 5 から 97 へ増えたためである。 除外の側の Critical 97件の CNA は Linux が 89件で、すべて Azure Linux のパッケージ勧告である。

「CVE 全体の Critical」だけを見ると、今月は重い月に見える。 本体相当に限ると、Critical も重い層も前月より少ない。どちらの母集団の数字かを確かめずに Critical の件数を比べないこと。

示唆と推奨アクション

以下は本レポートの分析に基づく推奨であり、確定した規制要求ではない。規制当局の個別の監督上の期待については、一次情報での確認を前提とする。

1. 監視指標（前号からの継続）

  • 「CVE件数」を脅威指標として使わない。今月は前月から 48.4% 増えたが、重い層は減り、本体相当の Critical も減った。件数の増減は、防御負荷とも危険度とも同じ向きに動いていない。

  • 変更管理を要する層の月次増減を追う。今月は本体相当で 93 から 79 へ減った。総数が最多の月でも、適用計画の重さは前月より軽いことがある。

  • ただし件数は作業量ではない。 対象が何製品に分散しているかで手間は変わる。本レポートは製品単位の分散を測っていない（前号と同じ限界）。

2. トリアージを深刻度ラベルから切り離す（前号からの継続）

  • 今月の Critical 174件に悪用確認は無い。悪用が確認された1件は Important である。悪用確認のあった月のうち、7月から10月までの4か月は、どれも Critical ではなかった。

  • 一方で5月には Critical の悪用確認があった。深刻度ラベルの上下で優先度を決めること自体が当てにならない、というのが4か月の記録の意味である。

  • 移行先は前号と同じく、CISA KEV と EPSS と資産の到達性の組み合わせ。

  • Critical の件数は母集団を確かめてから読む。 今月の全体の Critical 174件のうち 97件は Azure Linux の勧告である。

3. 緊急パッチ SLA

  • 今月の悪用確認1件（CVE-2026-96951）は、10月15日の取得時点で CISA KEV に収載されている。適用は当日に始める対象として扱う。是正期限は本レポートでは取得していない。 KEV の記載で確かめること。

  • 攻撃前提条件はベンダーの CVSS ベクタでは次のとおり。 ネットワーク経由で、事前の権限は不要、攻撃難易度は低い。ただしユーザー操作を要する。 影響はセキュリティ機能のバイパスで、記載上の原因はコマンドインジェクションである。CVSS 基本値は 8.8、影響製品は 31件である。

  • 時間的指標は「機能する実証コードあり」（E:F）で、CVRF の悪用状況の記載（悪用を検知）と一致している。

4. 自分の絞り込み規則を点検する（前号からの継続）

  • 前号で、KEV / EPSS の照合対象に「悪用が確認されている」を条件として足した。今月の照合対象は 1,164件（前月 786件）で、悪用確認の1件は対象に入り、KEV の新規収載として検出された。なお、この1件は外部クレジットがあるため、前号より前の条件でも対象に入っていた。

  • 公開済みだけのゼロデイは、照合の条件に入っていない。 今月の CVE-2026-92707 は照合の対象外で、EPSS の値を持たない。もう1件の公開済み（CVE-2026-108398）は別の条件で対象に入っている。本号では条件を変えていない。

  • 外部の脅威情報と自組織の資産を突き合わせるときは、突き合わせの対象から何が外れているかを、毎月の数字で確かめること。

5. Edge/Chromium 自動更新（前号からの継続）

  • 今月の CVRF には Edge/Chromium の勧告が1件も無い（前月は 24件）。理由は本レポートでは分からない。CVRF に載らないことは、Edge に修正が無かったことを意味しない。

  • 本項の要点は件数に依存しない。Electron/CEF を埋め込んだアプリ（Teams、Slack、VS Code など）は、ブラウザの自動更新の恩恵を受けない。 SBOM でこれらの依存を洗い出す意味は、件数が0の月でも変わらない。

6. AI 依存の BCP（前号から継続）

  • AI をワークフローに組み込む場合、最上位モデルへの依存は BCP の対象と位置づけ、モデル多重化とフォールバック設計を標準とする。

CVRF
